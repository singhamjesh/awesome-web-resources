## 📊 How to decide whether a repo is genuinely trending

Do not use total stars alone. Check these signals:

- **Star momentum:** Are stars increasing unusually quickly over the last day or week?
- **Recent activity:** Are maintainers actively merging changes and responding to issues?
- **Community interest:** Are there meaningful discussions, forks, contributors, or external write-ups?
- **Reproducibility:** Can you install and run the project using the documented steps?
- **License:** Is the license clear, and does it allow your intended use?
- **Security:** Are dependencies, install scripts, release artifacts, and permissions reasonable?
- **Project health:** Check open issues, releases, maintenance status, and known limitations.

A repository may go viral because of a useful tool, a new AI release, a social-media post, a controversy, or a coordinated promotion campaign. Investigate the reason rather than assuming popularity means quality.

## 🗓️ Trend entry template

Copy this template when you add a newly discovered repository:

```markdown
### [Repository Name](https://github.com/owner/repository)

- **Category:** AI / Developer Tools / Security / Other
- **Discovered on:** YYYY-MM-DD
- **Why it is interesting:** One or two sentences.
- **Trend evidence:** Link to GitHub Trending, release, discussion, or other evidence.
- **Language:** Check the repository's current language breakdown.
- **License:** Verify in the repository; write “Not verified” if unclear.
- **Setup difficulty:** Beginner / Intermediate / Advanced
- **Status:** Watching / Tested / Archived
```

## 🔁 Suggested maintenance routine

1. Open [GitHub Trending](https://github.com/trending) and select the time range or language you care about.
2. Review each candidate's README, releases, commits, license, and issue tracker.
3. Add promising discoveries with a date and evidence.
4. Recheck the list weekly; remove broken links and mark abandoned projects.
5. Keep the long-term resource directory in `README.md` and time-sensitive discoveries here.
