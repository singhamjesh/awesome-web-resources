# 🤝 Contributing to The Developer's Vault

Thanks for helping improve this directory! The goal is to make it easier for people to find useful websites and genuinely valuable open-source projects.

## What belongs here?

Good contributions include:

- Useful developer tools, APIs, documentation, and online playgrounds
- AI tools with a clear purpose and understandable terms
- High-quality learning platforms and practical tutorials
- Open-source projects with useful documentation
- Cybersecurity training labs and defensive security resources
- Design, productivity, data visualization, and accessibility tools
- Interesting projects with a clear explanation of why they matter

## Before submitting a link

1. **Check the URL.** Make sure it resolves to the intended site and does not redirect to an unrelated or suspicious destination.
2. **Write a useful description.** Explain what the resource does, not just what its name suggests.
3. **Choose one primary category.** Avoid unnecessary duplicate entries.
4. **Check trust and privacy.** Do not submit phishing pages, malware, doxxing tools intended for abuse, or services designed to violate privacy.
5. **For GitHub projects, inspect quality.** Review the README, recent commits, license, releases, open issues, installation steps, and security implications.
6. **Be honest about uncertainty.** If a site's purpose, license, or maintenance status is unclear, say so rather than guessing.
7. **Date trend claims.** “Trending” is time-sensitive. Include a date and a link to the evidence.
8. **Avoid private links.** Do not add session-specific URLs, private dashboards, invitation tokens, or links that reveal someone's activity without permission.

## Resource format

Add websites to the appropriate section of `README.md` using:

```markdown
| [Website Name](https://example.com/) | A concise, accurate description of what it does. |
```

For a GitHub project, use:

```markdown
| [Owner/Repository](https://github.com/owner/repository) | What it does and why it is useful. |
```

## Trend entry format

Add time-sensitive discoveries to `TRENDING.md`:

```markdown
### [Repository Name](https://github.com/owner/repository)

- **Category:** AI / Developer Tools / Security / Other
- **Discovered on:** YYYY-MM-DD
- **Why it is interesting:** Brief explanation.
- **Trend evidence:** Link to the relevant source.
- **Language:** Verify on GitHub.
- **License:** Verify in the repository.
- **Setup difficulty:** Beginner / Intermediate / Advanced
- **Status:** Watching / Tested / Archived
```

Do not invent star counts, rankings, licenses, languages, or trend momentum. If a detail has not been checked, mark it as unverified or leave it out.

## Pull request checklist

- [ ] The link points to the intended website or repository.
- [ ] The description is accurate and concise.
- [ ] The entry is in the correct category.
- [ ] Duplicate entries have been avoided.
- [ ] Licensing and safety concerns have been considered.
- [ ] Any claim that a project is trending includes a date and evidence.
- [ ] No private URLs, credentials, tokens, or personal information are included.

## Thank you

Every carefully reviewed contribution makes this directory more useful. Prioritize quality, clarity, and trust over the number of links.
